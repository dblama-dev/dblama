# Журнал улучшений db-manager

21 ноября 2026 года. Исходное состояние — `a1b32bf`. Для сравнения использовал повседневные задачи разработчика и поддержки на одноразовых данных.

## Дополнение. Привилегии по маске имени

В phpMyAdmin 5.2.3 открыл форму создания аккаунта, включил «Grant all privileges on wildcard name» и создал `qa_demo` на временной MySQL 8.4. Сервер сохранил `ALL PRIVILEGES` на базах по маске `qa\_demo\_%`. Обе экранированные черты обозначают буквальный знак подчёркивания. [Форма phpMyAdmin](audits/2026-11-21/phpmyadmin-wildcard.jpg)

- **Маска баз данных.** В редакторе привилегий откройте «Выбрать область». Кнопка префикса подставляет маску выбранного аккаунта. Можно также ввести свою, например `reports\_%`. Выберите отдельные права или отметьте «Все права для этой маски баз данных», проверьте изменения и примените. Сервер применяет выдачу ко всем таблицам в подходящих базах, включая базы, созданные позднее. Право делегирования включается отдельно. В db-manager открыл аккаунт из phpMyAdmin, снял `DELETE` и проверил, что `SELECT` сохранился. [Редактор маски](audits/2026-11-21/database-pattern.jpg)
- **Маска таблиц внутри одной базы.** Выберите «Существующие таблицы по маске», укажите базу и введите шаблон или подставьте префикс аккаунта. На экране видны точные имена и число совпадений. После применения у каждой из этих таблиц появляется отдельная выдача. При частичном выполнении форма показывает ошибки и позволяет повторить только неудавшиеся выдачи. В стенде `qa\_demo\_%` совпал с `qa_demo_orders` и `qa_demo_archive`. У `qaXdemo_internal` прав не появилось. Новые таблицы в эту разовую выдачу не входят. [Предпросмотр таблиц](audits/2026-11-21/table-pattern.jpg)
- В MySQL при нескольких пересекающихся масках для доступа к данным учитывается первая подходящая выдача. В MySQL с `partial_revokes=ON` символы подстановки в правах на базы считаются буквальными, поэтому редактор предлагает точные базы и подбор существующих таблиц. [Семантика MySQL GRANT](https://dev.mysql.com/doc/refman/8.4/en/grant.html)
- Обе операции используют штатные GRANT и REVOKE. Служебные таблицы и фоновые задания не требуются. Браузерные тесты входят под созданным аккаунтом, проверяют чтение подходящих таблиц и отказ для соседних имён. На MariaDB отдельно проверено, что отзыв права `DELETE` сохраняет `DELETE HISTORY`.
- На финальной сборке прошли по четыре браузерных сценария на MySQL 8.4 и MariaDB 11.4, включая прежний путь выдачи прав на одну точную базу. Прошли все 392 теста фронтенда, модульные тесты Go, ESLint, проверка типов и golangci-lint. На ширине 390 пикселей предпросмотр таблиц помещается в экран.
- В интеграционных тестах на обоих движках перечитал выдачи при `ANSI_QUOTES` и `sql_quote_show_create=0`. После выдачи всех доступных прав на конкретную таблицу редактор позволяет отозвать одно из них и сохранить остальные, включая ранее выданный `GRANT OPTION`. Сравнительный стенд удалён.

## Где попробовать изменения

1. В обзоре сервера MySQL откройте «Пользователи и привилегии», найдите аккаунт по имени или хосту и выберите базу среди его назначенных прав. Отметьте одно право. До сохранения редактор покажет, что именно будет выдано или отозвано.
2. В списке таблиц нажмите «Вставить» у нужной таблицы. «Сохранить и добавить ещё» оставляет форму открытой для следующей записи. Во вкладке «Данные» выберите столбцы, отфильтруйте записи и нажмите «Экспорт видимых столбцов (CSV)».
3. Откройте «Связи таблиц» в каталоге базы. Найдите таблицу по имени или названию колонки и перейдите по ссылке на другой конец внешнего ключа. Обе ссылки ведут в редактор структуры.

## Сравнение и выбор задач

- **Пользователи MySQL.** В исходной версии список показывал выданные разрешения. Для изменения одного права приходилось заново выбирать уровень и вручную вводить имена базы и таблицы. За ориентир взял переход от аккаунта к правам конкретной базы в phpMyAdmin. [Справка phpMyAdmin](https://docs.phpmyadmin.net/en/latest/privileges.html)
- **Строки.** Таблица поддерживает фильтры, сортировку, редактирование и копирование. Скрыть ненужные поля перед просмотром и экспортом было нельзя. В Adminer выбор столбцов используется и при выгрузке. [Справка Adminer](https://www.adminer.org/en/tips/)
- **Структура.** Проследил загрузку и сохранение определения таблицы. Прежняя форма объединяла отсутствие значения по умолчанию и пустую строку. Значения ENUM и SET она превращала в текст через запятую, поэтому сохранение соседнего поля могло изменить отдельные метки.
- **Связи.** В исходной версии db-manager внешние ключи редактировались внутри таблицы. Для поиска входящих ссылок приходилось открывать таблицы по очереди. В Adminer есть обзор всей схемы с внешними ключами. Для db-manager выбрал обзор связей с поиском и переходом к структуре обеих таблиц. [Возможности Adminer](https://www.adminer.org/en/)

## Ход проверки

- Запустил phpMyAdmin 5.2.3 и Adminer 5.5.1 в отдельных контейнерах и подключил оба к MySQL 8.4. Опубликованные порты привязал к loopback. Подготовил таблицы клиентов и заказов для проверки в трёх интерфейсах. Для повторной проверки db-manager добавил MariaDB 11.4 и PostgreSQL 17.
- До изменений выполнил модульные тесты Go. Для HTTP-тестов требуются локальные порты. При запуске с доступом к ним все пакеты прошли.

## Изменения в рабочей копии

- **Аккаунты.** Фильтр по имени или хосту. После создания открываются права нового аккаунта. Для существующего аккаунта можно перейти к конкретной области выдачи, отфильтровать права и увидеть выдачи и отзывы до применения. Параметры аккаунта, пароль и лимиты доступны отдельно.
- **Данные.** Выбранные столбцы сохраняются в ссылке на таблицу и используются при CSV-экспорте отфильтрованных строк. Скрытие первичного ключа сохраняет возможность изменить правильную запись. Из просмотра значения можно добавить фильтр равенства, включая пустую строку и NULL. Незавершённые условия фильтра сохраняются.
- **Вставка.** Добавил непрерывный ввод с отдельным сохранением каждой строки. Исправил гонки при чтении BLOB-файла и при завершении старого запроса после перехода к другой строке. Оба случая воспроизвёл регрессионными тестами до исправления.
- **Структура.** Явные варианты значения по умолчанию, отдельные упорядоченные элементы ENUM/SET и корректное повторное сохранение вычисляемых полей. Исправил случаи с пустой строкой, буквальным текстом NULL и кавычками внутри SQL-выражения. Добавление перед первой и после выбранной колонки доступно там, где порядок поддерживает СУБД.
- **Связи.** Новый обзор получает внешние ключи одним запросом к системному каталогу выбранной схемы. Составное ограничение сохраняет порядок пар. Имена с пробелами, % и зарезервированными символами URL потребовали поправить декодирование пути API при чтении и записи.
- **Навигация.** В каталоге сначала доступны действия с таблицами. Массовые операции появляются при выборе таблиц. Переключатель базы поддерживает поиск. Ширина боковой панели регулируется мышью и клавиатурой. Действия строки занимают меньше места в сетке.

## Что ещё отличается

- В каталоге MySQL и MariaDB можно скопировать выбранные таблицы в другую базу. Для клонирования одной таблицы под новым именем в той же базе пока нужен SQL.
- У ограничений `CHECK` пока нет отдельного редактора. Их можно создавать и менять через SQL-консоль.
- Обзор связей показывает внешние ключи таблиц выбранной базы или схемы. Для ежедневной работы выбрал поиск и прямые переходы. Раскладку диаграммы не требуется хранить в служебных таблицах.
- «SQL выборки» показывает выполненный запрос с параметрами. Выбор отображаемых столбцов влияет на сетку и CSV. Сама сетка загружает все доступные поля строки.

## Исправления после повторной проверки

- Пустое поле в одноколоночной CSV-выгрузке записывалось пустой строкой файла, которую CSV-импорт пропускал. Теперь такая запись представлена как `""`. Проверил чтение CSV с запятой, CSV с точкой с запятой и TSV с пустым полем, SQL NULL и буквальным текстом `\N`.
- В глобальных правах MySQL флаг делегирования уже выданного статического права мог перейти в запрос на выдачу нового динамического права. Проверил исправление через интерфейс на отдельном заблокированном аккаунте и прочитал результат через `SHOW GRANTS`. Аккаунт сохранил `SELECT WITH GRANT OPTION` и получил `BACKUP_ADMIN` без делегирования.
- На PostgreSQL 17 изменение соседнего столбца могло завершиться ошибкой, если от другого столбца зависело вычисляемое поле. Сохранение теперь пропускает неизменённый тип. Отдельно проверены включение и снятие `NOT NULL` у вычисляемой колонки, изменение длины соседней и сохранность данных. Форма показывает поддерживаемые действия для существующих и новых колонок.

## Проверки сборки

- `make build` собрал SPA и исполняемый файл Go со встроенным интерфейсом. Vite предупредил о размере основного JS-файла.
- `make backend-test` прошёл по всем пакетам Go. `npm --prefix web test` прошёл по 45 файлам, 360 тестов. `make lint` проверил Go, ESLint и типы TypeScript.
- В Chromium прошёл полный набор Playwright на трёх СУБД. MySQL — 31 сценарий, MariaDB — 31, PostgreSQL — 29. Два пропущенных на PostgreSQL сценария проверяют управление MySQL-аккаунтами и редактирование знаковых длительностей MySQL/MariaDB `TIME`. Среди проверок — составной внешний ключ, переход между базами или схемами, повторная вставка после ошибки, сохранение DEFAULT после ALTER и экспорт JOIN без повторного исполнения.
- После последней правки раскладки повторил по четыре браузерных сценария редактора структуры на MySQL и MariaDB. В обоих прогонах прошли все четыре.
- Проверил Go-пакеты с тегом `integration` на реальных СУБД. Первый общий запуск прервался. В итоговом прогоне проверил API и остальные пакеты, полный драйвер PostgreSQL и драйвер MySQL/MariaDB. Последний запустил четырьмя группами и сверил объединение с полным списком Go. Прошли все 123 теста верхнего уровня без пропусков.
- Пять контейнеров сравнительного стенда остановлены, выделенная сеть и временные файлы с паролями удалены. Локальная сборка приложения находится в `server/dbmanager`. Для пересборки используется `make build`.
