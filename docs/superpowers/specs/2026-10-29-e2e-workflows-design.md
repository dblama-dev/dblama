# E2E: пользовательские сценарии db-manager

Пользователь поручил автономно расширить проверку за пределы создания таблицы.

## Решение

Playwright Chromium → собранный SPA → Go API → настоящая тестовая СУБД.
Матрица: MySQL 8.4, MariaDB 11.4, PostgreSQL 17. Не подменяем API.
Компонентные тесты дополняют E2E на точечных регрессиях.

Рассмотрены: только Vitest (не ловит браузерные события и ошибки DDL), браузер
с mock API (не ловит несовместимые запросы), полный стек (выбран для этой задачи).

## Сценарии и критерии

| Сценарий | Действия пользователя | Проверяемый результат |
|---|---|---|
| Сессия | Вход, перезагрузка, выход, неверный пароль, повторный вход | Сессия переживает reload, защищённые страницы закрыты после logout, ошибка входа не ломает повтор |
| AUTO_INCREMENT | Включить, выключить, выбрать другую колонку | Отключается кликом; не более одного выбранного столбца |
| Новая таблица | id INT NOT NULL AUTO_INCREMENT + PRIMARY, текстовая колонка | Сохранение за один запрос, ключ и автоинкремент видны после reload |
| Изменение структуры | Добавить колонку, переименовать таблицу, повторно открыть | Изменения сохранены в БД и каталоге |
| Строки | Создать, изменить, скопировать, удалить; NULL и пустая строка | Реальные значения читаются обратно, новый ID при копировании |
| Выборка | Фильтр, сброс, сортировка, следующая страница | Возвращаются ожидаемые строки, фильтр сбрасывает страницу |
| Upsert | Вставить новую строку и обновить конфликтующий PK | Нет дубликата, изменено нужное значение |
| SQL | Несколько SELECT, ошибочный запрос, следующий корректный запрос | Несколько результатов; понятная ошибка; восстановление работы |
| Перенос данных | Экспорт SQL/CSV, импорт в тестовую таблицу | Скачанный файл валиден, после импорта восстановлены значения |
| Базы | Создать, переименовать, отменить удаление, подтвердить удаление | Каталог обновлён, отмена сохраняет БД, удаление требует точное имя |
| Views | Создать, прочитать, изменить, удалить | Изменение исходника меняет результат запроса |
| Мониторинг | Процессы, переменные, статус | Реальные данные сервера без ошибок |

## Границы и безопасность данных

Один отдельный контейнер БД на прогон; случайное имя контейнера и host port,
фиксированная тестовая БД. Объекты тестов имеют уникальный префикс e2e_.
Контейнер и приложение останавливаются даже при ошибке. Существующие контейнеры
и пользовательское приложение не используются. Приложение запускается обычным
бинарником без Docker. Режим внешней БД требует явной передачи параметров и
отдельной тестовой БД; очищаются только созданные тестом объекты.

Это начальная матрица критических сценариев, а не исчерпывающая проверка продукта:
управление пользователями, все виды routines/triggers/events/partitions,
многогигабайтные импорты, гонки, дополнительные браузеры — дальнейшее расширение.
