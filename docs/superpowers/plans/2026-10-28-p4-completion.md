Дата: 2026-10-28. Ветка: `p4-postgresql`, база: `master` (`5752632`).

Задачи 1–8 реализованы. П4 готов к интеграции; П5/П6 в эту работу не входят.

## Что завершено

- Выбор схемы, группы схем и sequences в дереве, создание/удаление sequences с подтверждением.
- Выбранная схема передаётся в запросах таблиц, структуры, индексов, строк, консоли, EXPLAIN, экспорта/импорта и sequences.

## Решения при завершении

1. Контекст запроса вместо API SetSchema. Причина: одна сессия обслуживает параллельные запросы. Цена: внутренняя передача schema через context во всех методах. SetSchema остаётся default для прямых вызовов драйвера.
2. Схема распространяется на консоль, transfer и sequence mutations. Причина: выбор схемы должен управлять всеми операциями. Цена: расширенная область проверок внутри П4.
3. Пул PostgreSQL обслуживает только БД входа. Другая БД отклоняется с предложением переподключиться. Цена: нет прозрачного переключения между БД в одной сессии; предотвращены операции над неверной БД.
4. CSV/TSV PostgreSQL: `\N` означает SQL NULL, пустое поле — пустую строку, начальный обратный слеш удваивается. JSON-массивы и bytea преобразуются обратно при импорте. Цена: старые CSV с пустым полем в значении NULL нужно преобразовать; MySQL-формат не изменён.
5. ForeignKey.refSchema хранится отдельно от refTable. Причина: точка может быть частью имени таблицы. Цена: добавлено необязательное поле API; имена не разбиваются по точкам.
6. Произвольный SQL использует физически удаляемое из пула соединение. Причина: Conn.Close возвращает SET/search_path в общий пул. Цена: новое соединение на запуск консоли/SQL-импорта.
7. Полная MySQL/MariaDB-матрица разбита на три группы; это не сокращение покрытия. Браузерный download/upload заменён API-проверкой из-за таймаута инструмента — остаётся ограничение ручной UI-проверки.

## Отложенные небольшие замечания

Из итогового ревью: отрицательный increment при создании sequence не поддержан UI и нормализуется драйвером; чтение комментариев колонок не включено в TableDef. Частично устаревшие комментарии о SetSchema обновлены.

Из предыдущего журнала П4: крайний случай маскирования пароля в ошибках malformed DSN; список БД без superuser может упасть при pg_database_size; создание контейнера на каждый тест медленное; нет отдельного composite-FK fixture; отсутствует defer Rollback на panic в execDDL; общий whitelist FK actions для MySQL/PG; предварительная проверка дублей индексов при CREATE; USER-DEFINED array label и обработка NaN требуют уточнения. Эти замечания не объявляются исправленными.

Уже отложенное ранее: потоковый SQL splitter, P5 views/triggers/routines/users/monitoring, перестановка/изменение generated-колонок и очистка комментариев согласно прежним ограничениям.
