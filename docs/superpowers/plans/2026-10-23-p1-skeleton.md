# db-manager v0.1 — План 1/6: Каркас приложения (walking skeleton)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Работающее приложение: вход под учёткой MySQL/MariaDB, обзор сервера (список БД), SPA-каркас с темой и i18n, CI.

**Architecture:** Один Go-бинарник (chi) обслуживает REST `/api/*` и отдаёт Vue-SPA через go:embed. Контракт драйвера в plan 1 минимален (`Info/Caps/ListDatabases/Close`) и наращивается планами 2–5. Сессии — in-memory store с janitor-TTL; учётка БД живёт только в памяти процесса.

**Tech Stack:** Go 1.23+ (chi/v5, go-sql-driver/mysql, testcontainers-go), Vue 3 + TS + Vite (Naive UI, Pinia, vue-router, vue-i18n, Vitest), npm.

**Spec:** `docs/superpowers/specs/2026-10-23-db-manager-design.md` (план аргументируется спекой; исполнитель читает оба документа).

Дорожная карта: П1 каркас (этот) → П2 MySQL-ядро (данные+структура) → П3 консоль+дампы → П4 PostgreSQL → П5 полный Adminer-набор + юзеры + мониторинг → П6 релиз. Каждый следующий план пишется перед своим исполнением.

## Global Constraints

- Go-модуль: `github.com/hitslab/db-manager/server` (переименование до релиза допустимо одной правкой go.mod).
- Go 1.23+, `CGO_ENABLED=0`. Go-зависимости этого плана: `github.com/go-chi/chi/v5`, `github.com/go-sql-driver/mysql`, `github.com/testcontainers/testcontainers-go` (test-only).
- Node 20+, npm; SPA-зависимости — latest stable на момент исполнения, lockfile коммитится.
- Cookie сессии: имя `dbm_session`, `HttpOnly; Secure; SameSite=Strict; Path=/`, ID = 32 байта crypto/rand в hex.
- Мутации (не GET/HEAD) требуют заголовок `X-Requested-With` ≠ пустого, иначе 403.
- Конверт ошибок: `{"error":{"code","message","detail"?,"sqlState"?,"driverCode"?}}`; коды: `auth_required, auth_failed, bad_request, not_found, driver_error, driver_not_supported, query_timeout, query_cancelled, rate_limited, internal`.
- Env и дефолты (спека §3): `LISTEN=:8080`, `SESSION_TTL=30m`, `LOGIN_RATE_LIMIT=10/min`, `TRUSTED_SERVERS` (пусто = выключен; формат `host:port,...`).
- Матрица интеграционных тестов этого плана: `mysql:8.4`, `mariadb:11.4` (контейнеры запускаются с root-паролем `dbmanager-test`, порт случайный от testcontainers).
- Коммиты: conventional commits; каждый таск заканчивается коммитом.
- Линт: golangci-lint (config `.golangci.yml` в `server/`), eslint + vue-tsc на фронте.
- Пароли/DSN никогда не логируются и не попадают в HTTP-ответы.

## Review Focus

Пять классов входных данных, которые спека подразумевает, но базовые happy-path тесты не трогают. Каждый закреплён тестом в таске-владельце:

1. **Неверный пароль/недостижимый хост при логине** → 401 `auth_failed` с сообщением драйвера, не 500, не утечка DSN. Тест: `TestLoginHandler_WrongPassword` (Task 7).
2. **Протухшая/выселенная сессия при запросе API** → 401 `auth_required`, UI уходит на `/login`. Тесты: `TestAuthMiddleware_RejectsUnknownSession` (Task 6), `router guard` (Task 11).
3. **Неизвестный driver id в логине** (в т.ч. `postgres` до плана 4) → 400 `bad_request`, не паника. Тест: `TestLoginHandler_UnknownDriver` (Task 7).
4. **Мутация без `X-Requested-With` с валидной сессией** → 403. Тест: `TestCSRFMiddleware_RejectsMissingHeader` (Task 6).
5. **Брутфорс: 11-я неудачная попытка логина с одного IP** → 429 `rate_limited`; удачные попытки бакет не тратят. Тест: `TestRateLimiter_TokenBucket` (Task 6) + `TestLoginHandler_RateLimited` (Task 7).
