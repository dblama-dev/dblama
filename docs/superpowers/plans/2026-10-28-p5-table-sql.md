# П5.1 — SQL определения таблицы: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Пользователь открывает раздел SQL существующей таблицы и видит её актуальное DDL в выбранной схеме.

**Architecture:** Драйверы MySQL/MariaDB и PostgreSQL уже реализуют `ShowCreateTable`; добавляем чтение через существующий API и отдельный компонент просмотра в `TableView`. Компонент получает определение заново при открытии, смене таблицы/схемы и ручном обновлении. Новые зависимости не нужны.

**Tech Stack:** Go, chi, Vue 3, TypeScript, Naive UI, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-23-db-manager-design.md`, §6 (`create-sql`), §8 (`view=sql`).

**Status:** Подготовлен; реализация не начата. Это первый небольшой пункт П5, а не весь этап.

## Global Constraints

- СУБД v0.1: MySQL 8+, MariaDB 10.11+, PostgreSQL 14+.
- Сессия и проверка доступа — существующие middleware; пароль не возвращается API.
- PostgreSQL: выбранная схема передаётся через `?schema=` и context, без изменения общей схемы драйвера.
- UI: русский и английский, тёмная и светлая темы, навигация через Vue Router с сохранением query.
- DDL показывается как текст; просмотр не исполняет SQL.
- Использовать изолированную рабочую ветку; не изменять завершённую реализацию П4 без необходимости.

## Review Focus

1. Имена с пробелами, Unicode и `%`: URL кодируется один раз, драйвер получает исходные имена — Task 1 и Task 2.
2. Медленный ответ старой схемы/таблицы не заменяет актуальный SQL, ошибку или loading — Task 2.
3. Режим `_new` не запрашивает DDL несуществующей таблицы — Task 2.
4. Ошибка доступа/драйвера не выглядит как успешно загруженный пустой SQL; после ошибки доступно повторное чтение — Task 1 и Task 2.
5. Повторное открытие SQL после изменения структуры получает новое определение; текст, похожий на HTML, не исполняется — Task 2.

**Interfaces:**
- Consumes: Task 1, ответ `{ sql: string }`; `api<T>(method, path)`; `catalog.path(path)` для выбранной схемы.
- Produces: компонент `TableSQL` с props `{ db: string; table: string }`, раздел `/db/:db/table/:t?view=sql`, кнопка обновления и видимые loading/error состояния.
- Имена: `table.sql` = `SQL` в обоих языках; `table.sqlLoading` = `Загрузка SQL…` / `Loading SQL…`; `table.sqlRefresh` = `Обновить` / `Refresh`.
- Неизвестный `view` по-прежнему открывает данные. У `_new` нет SQL-раздела; прямой `?view=sql` показывает структуру без обращения к create-sql.

- [ ] **Step 1: Добавить тесты компонента.** `TableSQL.test.ts`: ответ API виден в `<pre><code>`; кнопка обновления заменяет текст новым ответом; путь содержит кодированные имена и выбранную схему; смена props/схемы запрашивает актуальное определение; запоздавшие успешный и ошибочный ответы старого запроса не меняют экран; ошибка показывается, повторное обновление восстанавливает просмотр. Использовать управляемые Promise для проверки порядка ответов. Строка `CREATE TABLE "<img src=x onerror=alert(1)>" ...` должна отображаться текстом, без элемента `img`.

**П5 — функциональность v0.1:**

- Создание/удаление/переименование БД и выбор collation; сейчас есть только список БД.
- Перенос/копирование таблиц между БД; bulk API сейчас поддерживает drop/truncate.
- Views: чтение/редактирование определения и создание. Список и удаление уже есть.
- Триггеры, процедуры/функции; события и партиции MySQL/MariaDB.
- Пользователи, пароли, лимиты и привилегии MySQL/MariaDB.
- Мониторинг: процессы, kill, переменные и статус.
- Редактор FK и выбор значений из родительской таблицы при редактировании строки.
- Копирование строк, экспорт текущей выборки, BLOB-превью. Upsert есть в драйверах, но не подключён к пользовательскому сценарию/API строк.
- Форматирование SQL. Списки типов/collation/операторов пока не поступают из метаданных драйвера по контракту спецификации.
- Дополнить экспорт объектами views и согласовать оставшиеся расхождения со спецификацией: операции со строками без PK сейчас отключены в UI; generated-колонки имеют ранее принятые ограничения.
- Sequences PostgreSQL: backend умеет alter/restart, UI предоставляет создание/удаление; отрицательный increment пока не поддержан UI и нормализуется при создании драйвером.

**Технический долг П3/П4:** потоковый SQL splitter; маскирование пароля в malformed PG DSN; список PG БД без superuser; rollback при panic в DDL; валидация FK actions и дублей индексов; комментарии PG колонок; крайние случаи пользовательских массивов/NaN; ускорение интеграционных тестов и отдельная composite-FK fixture.
