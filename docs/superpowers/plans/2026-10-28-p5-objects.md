## Implemented contracts and verification

- `registerObjectRoutes(chi.Router)` mounts GET and PUT/DELETE by name for `/databases/{db}/{views,triggers,routines,events}`, procedure `/routines/{name}/call`, and table partition list/add/drop/truncate. Every handler checks both the advertised capability and optional interface. Lists return `{objects}` or `{partitions}`; calls return `{results}`. DELETE carries `kind`, `table`, `identity` query parameters. Save takes `{source,kind,table,identity}`; CALL takes `{args,identity}`.
- Object catalogs include CREATE source. PostgreSQL signatures are catalog-validated before DROP/CALL; selected schema remains request-scoped. PostgreSQL object saves use a transaction, including atomic trigger replacement, and raw extended-protocol `ExecParams` to reject extra statements. Regression discovery: pgx `Exec` forces simple protocol for zero-argument SQL despite an explicit execution mode.
- MySQL SHOW CREATE round-trips source, and procedure calls bind IN values, keep OUT/INOUT variables on a dedicated discarded connection, consume every result set, then return OUT/INOUT values. Routine/trigger/event edits preserve previous source and attempt restoration after a failed recreation. MySQL DDL replacement cannot guarantee restoration after disconnection or preserve object-specific grants; the SQL editor explains recreation semantics.
- Vue route exports `objectRoutes`; translations export `objectMessages`. Object browser/editor, source privileges explanation, JSON procedure calls, partition definitions, capability visibility, and explicit destructive confirmation are implemented. Tables may be selected for partitions; table-specific route is also exported.

## Foreign-key editing extension

- Added `ForeignKeyManager.SaveForeignKeys(ctx,db,table,desired)` and `ValidateForeignKeys(keys,requireNames)`. Validates mapping cardinality/order, duplicate/empty identifiers, action whitelist, dialect identifier lengths, local columns and schema semantics before mutation.
- Added `registerForeignKeyRoutes`: POST `/databases/{db}/tables/{table}/foreign-keys` with a full desired JSON array, `[]` clears constraints, `null` rejected. Authentication/CSRF/schema middleware is supplied by root.
- PostgreSQL preserves explicit referenced schema and applies drop/add statements through existing `execDDL` transaction. MySQL keeps user constraint names, commits numbered DDL steps, and attempts to restore the previous constraint if replacement fails. Earlier successful steps may remain applied; errors report the outcome.
- Engine discovery verified with Docker and official MySQL documentation: combined DROP/ADD of a same-name FK fails under COPY (duplicate constraint); INPLACE requires disabling FK checks. Per root direction and spec §4.6, use sequential DDL with compensating restoration rather than disabling referential checks or renaming constraints.
- `ForeignKeyEditor.vue` takes db/table/modelValue/columnNames, emits `update:modelValue` and `saved`, handles composite pairs, explicit referenced database/schema, referenced-column fetch, add/remove and actions. `_new` mode edits locally; root includes model in table CREATE. Existing-table mode has separate Save FK button.
- FK live lifecycle tests PASS on mysql:8.4, mariadb:11.4 and postgres:17: composite cross-schema add/change/drop, injected action rejection, old constraint retained/restored after invalid replacement.
- FK API unit test PASS; frontend three component tests PASS (ordered composite save, `_new` model updates, reference schema propagation). Type-check and frontend lint PASS.
